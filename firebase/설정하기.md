## 3. 교실에서 쓰기 전 확인할 것

1. 현황판을 열어 로그인하고 **[▶ 수업 시작]** 을 누릅니다.
2. 다른 기기(태블릿)에서 콘텐츠를 열고 번호를 입력합니다.
3. 현황판에 그 번호가 **1~2초 안에** 켜지는지 봅니다. (예전 판은 6초마다 새로 물었습니다)
4. 태블릿에서 다른 탭으로 갔다 오면 주황 → 초록으로 바뀌는지 봅니다.
5. 두더지 잡기를 끝까지 해서 점수가 점수판에 오르는지 봅니다.
6. **[■ 수업 종료]** 를 누른 뒤에는 태블릿 기록이 더 이상 쌓이지 않는지 봅니다.
7. 다음 날 달력에서 어제 날짜를 골라 그 수업이 그대로 보이는지 봅니다.

> 2026-09-18에 여기까지는 확인해 두었습니다 — 익명 로그인, 규칙이 막고 여는 것(로그인 없이 읽기·남의
> 기록 읽기·수업 안 열렸을 때 쓰기·번호 위조·시각 위조는 모두 거부), 수업이 열린 동안 학생 기록과
> 점수가 실제로 쌓이는 것까지. 현황판 화면은 구글 로그인이 있어야 열리므로 선생님이 한 번 열어 보셔야 합니다.

## 4. 무엇이 어디에 쌓이는가

```
mk/
├── current            지금 열린 수업 {ms, g, c}   ← 학생이 읽는 유일한 곳
├── sessions/<시작ms>  수업 {ms, g, c, end}
├── ev/<시작ms>/<id>   기록 묶음 {n, sid, st(서버시각), e:[{o,k,p,d,v,sc}]}
├── scores/<id>        점수 {st, g, c, n, p, sc, d}
└── names/<파일이름>   이름표에 없는 콘텐츠의 이름 (현황판이 배워서 적는다)
```

- 학생은 `current` 만 읽습니다. 남의 기록은 보지도 고치지도 못합니다.
- `current` 가 없으면(= 수업 시작 전) 학생 화면은 **아예 보내지 않습니다.**
  Apps Script 판에서 서버가 버리던 것과 같은 규칙인데, 이번에는 학교 무선망도 덜 씁니다.
- 시각은 기기 시계를 믿지 않습니다. 묶음을 보낼 때 서버가 `st` 를 찍고,
  묶음 안 이벤트의 앞뒤 간격(`o`, 0 이하)만 기기가 재서 현황판이 되살립니다.

학생 브라우저는 **번호를 입력한 뒤에야** 익명 계정을 받습니다. 받은 토큰은 그 브라우저에 남아
다음 시간에도 다시 씁니다. (번호를 넣지 않은 브라우저까지 계정을 만들면 한 반이 같은 학교 IP 로
몰릴 때 가입 한도에 걸립니다.) 익명 계정은 Authentication 목록에 쌓이므로, 학년이 끝나면
콘솔에서 지워도 됩니다. 지워도 학생은 다음에 열 때 새로 받습니다.

한 반 40분에 3,000건 남짓, 하루 5교시면 2MB 안팎입니다. 무료 한도(1GB)에는 여유가 많지만
학기마다 한 번씩 현황판의 **[🧹 기록 정리]** 로 지난 기록을 지우면 깔끔합니다.
(점수 기록은 역대 최고 때문에 지우지 않습니다)

## 5. 되돌리고 싶을 때

`assets/track.js` 의 `FB.databaseURL` 을 `""` 로 비우고 커밋하면
학생 화면은 곧바로 예전 Apps Script 현황판으로 돌아갑니다. 다른 것은 손대지 않아도 됩니다.

지금까지 시트에 쌓인 기록은 그대로 있습니다. 옛 현황판(스프레드시트의 웹앱 주소)도
그대로 열리므로, 지난 학기 기록을 볼 일이 있으면 그쪽에서 보면 됩니다.
